# Opt-in engine compatibility patch

This isolated offline candidate patches the pinned XMage `ApprovingObject` constructor only. A resolved cast permission can remain valid after the source card owner leaves a multiplayer game. If no live source object exists and either stack LKI is absent or the retained state has advanced past the actual stack LKI incarnation, its reference uses the retained game-state zone-change counter, matching the preceding live card identity. This fallback requires a positive captured ability stack-moment counter and a retained state counter at least that large. Never-activated unknown sources retain the original diagnostic path. The positive captured identity is the bounded provenance check; no new reflective state access is introduced. Existing live-object, same-incarnation stack-LKI and null-source paths remain unchanged. Stale stack LKI must not replace the later graveyard identity after owner departure.

The patch does not remove permissions, suppress a logger, alter costs, extend durations, or avoid particular cards. Mission Briefing stolen by Etali exposed the upstream reference-lifetime defect. Cast permissions and exile replacement effects must remain functional until their normal expiry.

The baseline engine checkout and JAR remain immutable. Build a separate copied Mage module using the pinned root POM and dependency repository, overlay this one source file, and package only that module. Artifact provenance must record the baseline and candidate core hashes, exact AI JAR hash and combined runtime classpath. This source preparation alone is not acceptance evidence; fresh actual lifetime tests and the complete engine suite are required before any new soak.
